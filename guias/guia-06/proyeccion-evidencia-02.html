Paso 1 · Análisis del Negocio

Paso 1: Identificar Entidades, Atributos y Llaves

La técnica rápida para extraer los elementos de tu base de datos a partir de lo que hace tu software.

1. Entidad

¿Qué objetos maneja el sistema?

Son los sustantivos o cosas principales sobre las cuales necesitas guardar registros.

• CLIENTE
• PRODUCTO
• FACTURA / VENTA
• VEHICULO / PACIENTE
Regla: Se escriben en MAYÚSCULA y en singular.
2. Atributos

¿Qué datos describen a la entidad?

Son las características o propiedades individuales que almacenarás de cada objeto.

• nombre, telefono, correo
• precio, stock, descripcion
• fecha_creacion, estado
Regla: Deben ser simples y atómicos (no listas).
3. Llave Primaria (PK)

¿Cómo diferencias cada registro?

El identificador único obligatorio que no se puede repetir nunca en la tabla.

• id_cliente (número autoincremental)
• numero_documento (cédula)
• placa (en caso de vehículos)
Regla: Ninguna tabla puede existir sin Llave Primaria.
Ejemplo Claro de Lectura: "El cliente solicita una cita con el médico". → Entidad 1: CLIENTE | Entidad 2: MEDICO | Relación: SOLICITA CITA.
Paso 2 · Diagramación Conceptual

Paso 2: Dibujar el Diagrama Conceptual (MER)

Cómo plasmar gráficamente las entidades y sus conexiones mediante figuras sencillas.

Simbología del Diagrama Conceptual (Chen)

[ Rectángulo ] Representa una Entidad (ej. CLIENTE)
< Rombo > Representa la Relación (ej. Realiza)
( Óvalo / Elipse ) Representa un Atributo (ej. Nombre)
( Óvalo Subrayado ) Representa la Llave Primaria

Herramienta recomendada para este diagrama conceptual: draw.io (gratuita en navegador).

Los 3 Tipos de Relación (Cardinalidad)

1 a 1 (Uno a Uno): Un registro se asocia solo con uno del otro lado (ej. Un USUARIO tiene un único PERFIL).
1 a Muchos (1:N) — La Más Común: Un registro del lado 1 tiene varios del lado N (ej. Un CLIENTE realiza muchas COMPRAS).
Muchos a Muchos (N:M): Varios registros se asocian con varios (ej. Una VENTA tiene muchos PRODUCTOS y un producto está en muchas ventas).
⚠️ Toda relación Muchos a Muchos (N:M) se convertirá en una tabla intermedia en el siguiente paso.
Paso 3 · Transformación al Modelo Relacional

Paso 3: Las 3 Reglas para Pasar a Tablas

Aplica estas 3 reglas mecánicas para no cometer ningún error de diseño.

REGLA 1

Entidades se vuelven Tablas

Cada entidad identificada se convierte directamente en una tabla. Sus atributos pasan a ser las columnas de la tabla.

Tabla: CLIENTES
- id_cliente (Llave Primaria)
- nombre
- correo
REGLA 2 · CLAVE

Relación 1 a Muchos (1:N)

La Llave Primaria de la tabla del lado "1" viaja como Llave Foránea (FK) a la tabla del lado "Muchos".

Tabla: PEDIDOS
- id_pedido (Llave Primaria)
- fecha
- id_cliente (Llave Foránea)
REGLA 3 · INTERMEDIA

Relación Muchos a Muchos (N:M)

Crea obligatoriamente una nueva tabla intermedia que une a ambas tablas y guarda datos propios de esa acción.

Tabla: DETALLE_PEDIDO
- id_detalle (Llave Primaria)
- id_pedido (Llave Foránea)
- id_producto (Llave Foránea)
- cantidad, subtotal
✅ En resumen: Nunca coloques listas de productos separados por comas. Siempre que algo se repita, se soluciona con una Llave Foránea o con una tabla intermedia.

Paso 5 · Herramienta Oficial de Práctica

Paso 5: Modelar en MySQL Workbench y Generar Script SQL

Cómo armar el diagrama visual en la herramienta oficial y obtener el script de creación de base de datos.

1. Crear Nuevo Diagrama:

Abre Workbench → File > New Model (o Ctrl + N) → Doble clic en Add Diagram.

2. Crear las Tablas:

Presiona la tecla T y haz clic en el lienzo. Doble clic en la tabla para agregar las columnas y marcar PK (Llave Primaria) y NN (No Nulo).

3. Trazar las Relaciones con Pata de Gallo:

Selecciona la herramienta 1:n Non-Identifying Relationship. Haz clic primero en la tabla hija (lado Muchos) y luego en la tabla padre (lado 1). Workbench crea la Llave Foránea solo.

4. Exportar Imagen para el PDF:

Ve a File > Export > Export as PNG... para guardar la imagen nítida que pegarás en tu informe formal.

Generación de Script SQL Ingeniería Hacia Adelante

Para obtener el código SQL ejecutable a partir de tu diagrama visual:

1. Presiona Ctrl + G (o menú Database > Forward Engineer).
2. Avanza con Next hasta la pantalla del código generado.
3. Haz clic en Copy to Clipboard (Copiar al portapapeles) y pégalo en el anexo de tu documento.
💡 Si Workbench genera el código sin errores, significa que tu diseño relacional es 100% válido.
Plantilla Guía Resuelta

Ejemplo Resuelto: Las 5 Tablas del Sistema de Ventas

Puedes tomar esta misma estructura lógica y adaptarla a tu propio proyecto formativo.

1. CATEGORIAS Catálogo
• id_categoria [PK, INT]
• nombre [VARCHAR(50)]
• descripcion [VARCHAR(200)]
2. PRODUCTOS Principal
• id_producto [PK, INT]
• id_categoria [FK, INT]
• nombre [VARCHAR(100)]
• precio [DECIMAL(10,2)]
• stock [INT]
3. CLIENTES Personas
• id_cliente [PK, INT]
• cedula [VARCHAR(20), Único]
• nombres [VARCHAR(120)]
• telefono [VARCHAR(20)]
• correo [VARCHAR(100)]
4. VENTAS (Cabecera) Transacción
• id_venta [PK, INT]
• id_cliente [FK, INT]
• fecha [DATETIME]
• total [DECIMAL(10,2)]
• estado [VARCHAR(20)]
5. DETALLE_VENTAS (Tabla Intermedia) Rompe relación N:M
• id_detalle [PK, INT]
• id_venta [FK, INT]
• id_producto [FK, INT]
• cantidad [INT]
• precio_unitario [DECIMAL(10,2)]
• subtotal [DECIMAL(10,2)]
🩺 En Veterinaria/Salud: Cambias Cliente por PACIENTE, Venta por CONSULTA y Detalle por TRATAMIENTO. 🔧 En Taller: Cambias por VEHICULO, ORDEN_SERVICIO y REPUESTOS.
