Fundamentos de Bases de Datos No Relacionales

¿Qué es NoSQL? Las 4 Familias Tecnológicas

NoSQL significa "Not Only SQL" (No Solo SQL). Diseñadas para esquemas flexibles y alta velocidad.

ESTÁNDAR SENA

1. Documentales

Guardan la información en documentos semiestructurados tipo JSON/BSON.

Motor: MongoDB, CouchDB
Uso: Catálogos, ventas, blogs y perfiles.
ULTRA-RÁPIDAS

2. Clave - Valor

Guardan un valor asociado a una clave única en memoria RAM.

Motor: Redis, DynamoDB
Uso: Sesiones de usuario, carritos temporales y caché.
BIG DATA

3. Columnas Anchas

Estructura de tablas cuyas columnas varían dinámicamente por registro.

Motor: Cassandra, ScyllaDB
Uso: Sensores IoT, telemetría y métricas masivas.
RELACIONES VIVAS

4. Grafos

Basadas en nodos y aristas para navegar conexiones complejas.

Motor: Neo4j, Neptune
Uso: Redes sociales y sistemas de recomendación.
💡 Conclusión: En el tecnólogo ADSO nos enfocamos en Bases de Datos Documentales con MongoDB porque es el estándar moderno en aplicaciones web y móviles (MERN Stack).
Glosario Técnico en Español

Tabla de Equivalencias: De Tablas SQL a Documentos NoSQL

Aprende a traducir mentalmente cada elemento del modelo relacional al modelo de MongoDB.

Término en SQL (MySQL) Término en MongoDB (NoSQL) Diferencia Fundamental
Base de Datos (Database) Base de Datos (Database) Es igual. Contiene las colecciones de tu proyecto.
Tabla (Table) Colección (Collection) No exige columnas fijas previas. Almacena documentos de un mismo tema.
Fila / Registro (Row) Documento (Document) Es un objeto en formato JSON/BSON con sus propios campos y listas.
Columna (Column) Campo (Field) Par clave-valor. Puede contener subdocumentos u arreglos anidados.
Llave Primaria (PK) Campo _id (ObjectId) Identificador único generado automáticamente por MongoDB de 12 bytes.
Cruces con JOIN Incrustación / $lookup Se prefiere incrustar los datos hijos en lugar de cruzar múltiples tablas.
✅ Para recordar: En MySQL creas Tablas con Filas. En MongoDB creas Colecciones con Documentos.
Formato de Almacenamiento

Anatomía de un Documento: JSON y BSON

Escribimos en JSON legible y MongoDB lo guarda internamente en BSON binario optimizado.

Tipos de Datos Soportados:
  • • Texto (String): Cadenas de caracteres entre comillas dobles.
  • • Numérico (Int / Double): Enteros o decimales directos sin comillas.
  • • Booleano (Boolean): Valores de verdad: true o false.
  • • Fecha (Date / ISODate): Marcas de tiempo exactas universales.
  • • Arreglo (Array / Listas): Colecciones de datos entre corchetes [ ].
  • • Objeto / Subdocumento: Datos anidados entre llaves { }.
📏 Regla Técnica: Un solo documento puede medir hasta 16 MB. Si necesitas guardar miles de registros subordinados, usa referenciación.
Ejemplo de Documento BSON Colección: clientes 
{
  "_id": ObjectId("664f1a2b8c9d0e1f2a3b4c5d"),
  "nombres": "Mariana López García",
  "documento": "1082456789",
  "estado": "Activo",
  "puntos_fidelizacion": 150,

  // Lista de valores (Arreglo)
  "etiquetas": ["frecuente", "mayorista"],

  // Subdocumento anidado (Incrustación)
  "contacto": {
    "correo": "mariana.lopez@gmail.com",
    "celular": "3158765432",
    "ciudad": "Garzón"
  },
  "creado_en": ISODate("2026-09-23T10:00:00Z")
}
Todo lo que describe a Mariana está en un solo documento sin necesidad de hacer cruces con otras tablas.
Regla de Oro en NoSQL

Decisión de Diseño: ¿Incrustar o Referenciar?

La justificación técnica de esta decisión es obligatoria en el informe para obtener calificación Aprobada ('A').

OPCIÓN A

Incrustar (Subdocumentos Anidados)

Los datos relacionados se guardan dentro del documento padre.

Úsalo cuando:
  • Es una relación de 1 a pocos (ej. los teléfonos de un usuario o los renglones de una factura).
  • Los datos casi siempre se leen juntos al consultar el documento principal.
  • Si se elimina el documento principal, los datos hijos deben desaparecer.
{ _id: 1, factura: "001", items: [ {prod: "Pan", cant: 2} ] }
OPCIÓN B

Referenciar (Por Identificador ObjectId)

Los datos se guardan en otra colección separada y se enlazan guardando solo el _id.

Úsalo cuando:
  • Es una relación de 1 a muchísimos (ej. miles de comentarios o logs de auditoría).
  • Son catálogos independientes que se usan en muchas partes y cambian de precio frecuentemente.
  • Para evitar que el documento supere el límite de 16 MB.
{ _id: 1, cliente_id: ObjectId("664f1...") }

Descarga de MongoDB Compass: Instalación y Conexión

La interfaz gráfica oficial para administrar bases de datos MongoDB de forma visual e intuitiva.

Enlace Oficial de Descarga Gratuita

MongoDB Compass está disponible para Windows (instalador .exe), macOS y Linux sin costo alguno.

Portal Oficial de Descarga: Descargar MongoDB Compass (Windows) URL: mongodb.com/try/download/compass
Pasos de Instalación:
  1. Descarga el instalador Compass (MSI or EXE).
  2. Ejecuta el asistente y completa la instalación típica.
  3. Al abrir, te pedirá una Cadena de Conexión (Connection String).
CONEXIÓN INICIAL

¿Cómo Conectarse en Compass?

Opción 1: Servidor Local (tu PC) mongodb://localhost:27017 Si instalaste el servicio de MongoDB Community en Windows.
Opción 2: Clúster en la Nube (MongoDB Atlas) mongodb+srv://usuario:clave@testingapps.mongodb.net Clúster gratuito de 512 MB proporcionado por MongoDB en la nube.
💡 Haz clic en el botón verde "Connect" y entrarás a la pantalla principal de bases de datos.
Taller Visual Paso a Paso

Práctica en Compass: El Botón "+ Create Database"

Cómo crear la base de datos de tu proyecto y su primera colección desde la interfaz de Compass.

Procedimiento en Pantalla

Paso 1: Clic en "+ Create Database"

En la esquina superior derecha de Compass verás el botón verde + Create database. Haz clic allí para abrir la ventana modal.

Paso 2: Diligenciar los 2 Campos Obligatorios

• Database Name: El nombre de la base de datos de tu proyecto (ej. adso_veterinaria, adso_tienda).
• Collection Name: El nombre de tu primera colección en plural (ej. productos, pacientes).

¿Por qué pide ambos nombres al tiempo?

En MongoDB no existen bases de datos vacías. El motor solo crea físicamente la base de datos en disco cuando tiene al menos una colección con documentos.

productos
Before MongoDB can save your new database, a collection name must also be specified at the time of creation.

La Consola MONGOSH: Comandos Básicos de Navegación

Aprende a abrir y usar el shell oficial que viene integrado en la parte inferior de MongoDB Compass.

¿Cómo abrir la consola MONGOSH?

En la barra superior derecha o en la pestaña inferior de MongoDB Compass, haz clic en el botón ">_ Open MongoDB shell" (o >_ MONGOSH).

Comandos de Navegación Esenciales:
1. show dbs Muestra todas las bases de datos que tienen datos guardados.
2. use mi_proyecto_dev Selecciona o crea la base de datos de trabajo activa.
3. show collections Lista todas las colecciones que existen dentro de la base de datos activa.
>_ MONGOSH (Consola Integrada) Atlas / Local 
// 1. Ver qué bases de datos existen en el servidor
test> show dbs
admin             40.00 KiB
config            12.00 KiB
adso_ventas_dev   64.00 KiB

// 2. Cambiarse a la base de datos del proyecto
test> use adso_ventas_dev
switched to db adso_ventas_dev

// 3. Ver qué colecciones existen adentro
adso_ventas_dev> show collections
clientes
pedidos
productos
El prompt de la consola siempre te muestra entre corchetes el nombre de la base de datos en la que estás trabajando.
Operaciones de Escritura

Comandos de Inserción: insertOne() e insertMany()

Cómo insertar documentos reales en tus colecciones desde la consola de MongoDB Compass.

UN SOLO DOCUMENTO insertOne()

Insertar un Registro Único

Inserta un único objeto entre llaves { }. Si no le colocas el campo _id, MongoDB lo crea automáticamente.

db.productos.insertOne({ nombre: "Café Especial Huila 500g", categoria: "Alimentos", precio: 24000.00, stock: 45, disponible: true });
✅ Respuesta: { acknowledged: true, insertedId: ObjectId(...) }
VARIOS DOCUMENTOS insertMany()

Insertar Múltiples Registros en Lote

Inserta una lista de documentos encerrados entre corchetes [ { }, { } ]. Ideal para poblar datos de prueba.

db.productos.insertMany([ { nombre: "Miel de Abejas 250ml", precio: 18000.00, stock: 20 }, { nombre: "Panela Orgánica 1kg", precio: 7500.00, stock: 80 } ]);
✅ Inserta todos los documentos en una sola operación atómica.
Operaciones de Lectura

Consultas y Filtros: El Comando db.coleccion.find()

Cómo buscar registros específicos utilizando operadores de comparación en MONGOSH.

CONSULTA GENERAL

Consultar Todos

Equivale al SELECT * FROM tabla de SQL. Trae todos los documentos de la colección.

db.productos.find();

Puedes agregar .limit(5) para limitar a los primeros 5 resultados.

FILTRO EXACTO

Filtro por Campo

Equivale al WHERE categoria = 'Alimentos'. Pasas un objeto con la condición de búsqueda.

db.productos.find({
  categoria: "Alimentos"
});
OPERADORES

Mayor Que ($gt)

Equivale a WHERE precio >= 20000. Usa operadores como $gt, $gte, $in.

db.productos.find({
  precio: { $gte: 20000 }
});

Reglas de Integridad Oficiales

Validación de Esquemas: Instrucción $jsonSchema

Cómo proteger tu base de datos para que rechace documentos sin campos requeridos o con tipos incorrectos.

¿Cómo funciona la regla?

Al crear una colección con db.createCollection(), puedes adjuntar un validador que evalúa cada documento antes de guardarlo en disco.

Parámetros Clave:
• required: Lista de campos obligatorios.
• bsonType: Tipo obligatorio (string, int, double, bool).
• minimum: Valor numérico mínimo permitido.
✅ Incluir este bloque en tu evidencia garantiza que tu entrega obtenga calificación sobresaliente.
Script de Validación Colección: clientes 
db.createCollection("clientes", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["nombres", "documento", "estado"],
      properties: {
        nombres: {
          bsonType: "string",
          description: "El nombre debe ser un texto obligatorio"
        },
        documento: {
          bsonType: "string",
          description: "Cédula obligatoria"
        },
        estado: {
          enum: ["Activo", "Inactivo"],
          description: "Solo admite 'Activo' o 'Inactivo'"
        }
      }
    }
  }
});
Si alguien intenta insertar un estado diferente a "Activo" o "Inactivo", MongoDB lo bloqueará de inmediato.
Plantilla Guía Resuelta

Caso Real Resuelto: Colección de Pedidos con Ítems Incrustados

Un diseño completo que puedes tomar de modelo para tu propio proyecto de grado ADSO.

Colección: pedidos 1 Documento Completo 
{
  "_id": ObjectId("664f33b1e2a84c001f5e89a1"),
  "numero_factura": "FAC-2026-0042",
  "fecha": ISODate("2026-09-23T15:20:00Z"),
  "estado": "Entregado",
  
  // 1. Referencia al Cliente (Referencing por ID)
  "cliente_id": ObjectId("664f1a2b8c9d0e1f2a3b4c5d"),
  "cliente_nombre": "Carlos Andrés Pérez",

  // 2. Ítems Comprados (Incrustación / Embedding)
  "items": [
    {
      "producto_id": ObjectId("664f2010c7a10f002a9b1101"),
      "descripcion": "Café Especial Huila 500g",
      "cantidad": 3,
      "precio_unitario": 24000.00,
      "subtotal": 72000.00
    }
  ],
  "total_pagar": 72000.00,
  "metodo_pago": "Transferencia Bancaria"
}
¿Por qué es el diseño perfecto?

El precio unitario de los productos queda congelado en el pedido, garantizando que el historial de facturación no se altere si el catálogo sube de precio.

Cómo adaptarlo a otros proyectos:
• Veterinaria: La mascota tiene una lista de vacunas: [{fecha, nombre, dosis}] incrustadas.
• Taller: La orden tiene una lista de repuestos: [{nombre, cant, costo}] incrustados.
• Restaurante: La comanda tiene una lista de platos: [{nombre, notas, precio}] incrustados.
