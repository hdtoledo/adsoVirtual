Marco Conceptual ANSI SQL

¿Qué es DDL y qué es DML en Bases de Datos Relacionales?

Teoría Obligatoria

El lenguaje SQL (Structured Query Language) se organiza formalmente en subconjuntos de instrucciones según la acción que realizan sobre el motor de base de datos:

DDL: Data Definition Language

Lenguaje de Definición de Datos

Define, modifica y elimina la estructura física de los contenedores y objetos de la base de datos (tablas, índices, vistas, schemas). No manipula filas individuales.

CREATE: Crea bases de datos, tablas e índices.
ALTER: Modifica columnas, tipos o llaves.
DROP / TRUNCATE: Elimina tablas o vacía su estructura.
DESCRIBE / SHOW: Inspecciona metadatos y esquemas.
Efecto: Produce confirmación automática (Auto-commit implícito).

DML: Data Manipulation Language

Lenguaje de Manipulación de Datos

Permite gestionar las filas y registros de datos contenidos dentro de las tablas existentes sin alterar la estructura de las columnas.

SELECT: Consulta y recupera registros (Query).
INSERT: Agrega nuevas filas a una tabla.
UPDATE: Modifica valores de registros existentes.
DELETE: Elimina filas específicas bajo condición WHERE.
Efecto: Puede ser transaccional (COMMIT / ROLLBACK).

Punto 1 del Taller • Comando DDL

Creación de la Tabla "libreta"

CREATE TABLE

La guía solicita: "Cree una tabla llamada 'libreta'. Debe tener los siguientes campos: nombre (cadena de 20), domicilio (cadena de 30) y teléfono (cadena de 11)":

// Sentencia SQL exacta:
CREATE TABLE libreta (
  nombre VARCHAR(20),
  domicilio VARCHAR(30),
  telefono VARCHAR(11)
);
Resultado: 0 row(s) affected, 1 warning (o 0.01 sec)

¿Por qué VARCHAR(n)?

  • VARCHAR almacena solo los caracteres reales más 1 byte de longitud, ahorrando espacio en disco frente a CHAR.
  • telefono varchar(11): Es una buena práctica almacenar teléfonos como texto para preservar ceros a la izquierda y caracteres especiales (+, -).

Punto 4 del Taller • Comando DML

Inserción de los Primeros Registros en "libreta"

INSERT INTO

La guía solicita ingresar textualmente los dos siguientes registros:

// Inserción múltiple atómica:
INSERT INTO libreta (nombre, domicilio, telefono)
VALUES
  ('Alberto Mores', 'Colon 123', '4234567'),
  ('Juan Torres', 'Avellaneda 135', '4458787');

También es 100% válido realizarlas en sentencias INSERT separadas.

Resultado esperado: 2 row(s) affected (0.00 sec)

Reglas DML Clave:

  • Uso de comillas simples (' '): Todo valor de texto alfanumérico (VARCHAR) debe encerrarse obligatoriamente entre comillas simples en el estándar SQL.
  • Correspondencia de orden: El orden de los valores en la cláusula VALUES debe coincidir exactamente con el orden declarado en las columnas (nombre, domicilio, telefono).
  • Nombres sin comillas: El nombre de la tabla y los campos no llevan comillas simples (opcionalmente llevan backticks `libreta`).

Punto 5 del Taller • Consulta DML

Seleccione y Muestre Todos los Registros

SELECT * FROM libreta

La guía solicita: "Seleccione y muestre todos los registros de la tabla". Se emplea la sentencia de consulta fundamental de SQL:

El asterisco (*) actúa como comodín para indicar al motor que proyecte todas las columnas de la tabla.

Equivalente formal:

Punto 6 del Taller • Modificación DML

Construya las Sentencias que Actualicen los Datos

UPDATE libreta SET ... WHERE

La guía solicita: "Construya las sentencias que actualicen los datos que acaba de insertar". Dado que la tabla libreta no tiene clave primaria (PK), en MySQL Workbench se debe ejecutar previamente SET SQL_SAFE_UPDATES = 0; para evitar el Error 1175:

Registro 1: Alberto Mores Nuevo domicilio y teléfono
// 1. Desactivar Safe Mode en la sesión:
SET SQL_SAFE_UPDATES = 0;

// 2. Actualizar registro:
UPDATE libreta
SET domicilio = 'Colon 456',
    telefono = '4239999'
WHERE nombre = 'Alberto Mores';

Rows matched: 1 Changed: 1 (Query OK)

Registro 2: Juan Torres Nuevo teléfono
// Actualizar teléfono:
UPDATE libreta
SET telefono = '4450000'
WHERE nombre = 'Juan Torres';

// (Opcional) Reactivar Safe Mode:
SET SQL_SAFE_UPDATES = 1;

Rows matched: 1 Changed: 1 (Query OK)

¿Por qué ocurre el Error Code: 1175 en MySQL Workbench y cómo resolverlo?

Causa: MySQL Workbench tiene activada por defecto la protección "Safe Updates", la cual rechaza cualquier UPDATE o DELETE si la cláusula WHERE no utiliza una columna que sea Llave Primaria (Primary Key). Como la tabla libreta creada en el taller no tiene llave primaria, el motor bloquea la modificación por seguridad.

Solución 1 (Inmediata en SQL - Recomendada): Ejecutar la línea SET SQL_SAFE_UPDATES = 0; en la misma pestaña de Workbench antes de ejecutar el UPDATE.
Solución 2 (Permanente en Workbench): Menú Edit > Preferences... > SQL Editor > desmarcar "Safe Updates (rejects UPDATEs and DELETEs with no key in WHERE)" > OK > Menú Query > Reconnect to Server.

Punto 8 del Taller • Función de Agregación

Cuente Cuántos Registros se Ingresan

SELECT COUNT(*)

La guía solicita: "Cuente cuántos registros se ingresan". En SQL se emplea la función de agregación estándar COUNT():

// Consulta con alias personalizado:
SELECT COUNT(*) AS total_contactos
FROM libreta;

COUNT(*) evalúa el número total de tuplas físicas en la tabla, independientemente de si algún campo individual contiene valores NULL.

La cláusula AS total_contactos asigna un nombre claro a la columna de salida.

Resultado Esperado en la Cuadrícula:

total_contactos
7
Verificación matemática: 2 registros del paso 4 + 5 registros del paso 7 = exactamente 7 registros totales.
