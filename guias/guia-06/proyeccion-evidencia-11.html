Concepto base

HTML, CSS y JavaScript: cada uno con una responsabilidad

Piensa en una casa: primero se levanta la estructura, luego se pintan y decoran los espacios y al final se instala la electricidad para que las cosas funcionen.

HTML

Estructura y significado: ¿qué es cada cosa?

Es la obra negra: define que algo es un título, una lista, una imagen o un botón. Sin HTML no hay contenido.

<button class="tema-toggle">
  Modo oscuro
</button>

CSS

Presentación: ¿cómo se ve?

Son la pintura y los acabados: colores, tipografía, espacios y la organización en pantalla (Flexbox y Grid).

.tema-toggle {
  border-radius: 0.75rem;
  width: 3rem;
}

JavaScript

Comportamiento: ¿qué hace?

Es la instalación eléctrica: responde a clics y teclas, valida datos y cambia la página sin recargarla.

boton.addEventListener('click', () => {
  aplicarTema('dark');
});

Separación de responsabilidades. Separar las capas en archivos distintos (index.html, styles.css, main.js) hace el código más fácil de leer, reutilizar y mantener. Además aplicamos mejora progresiva: la página se lee sin CSS y funciona sin JavaScript; cada capa suma, ninguna es obligatoria para acceder al contenido.

Paso 1 · Organizar

Una carpeta por tipo de archivo

Antes de escribir código se define dónde vive cada cosa. Esta estructura es el estándar de un sitio estático y es la misma que entregarás en el ZIP.

estructura del proyecto 
aa4-ev01-cafe/            ← carpeta del proyecto (la que se comprime)
├── index.html            ← estructura: la página de entrada
├── css/
│   └── styles.css        ← presentación
├── js/
│   └── main.js           ← comportamiento
└── img/
    ├── logo.svg
    ├── hero.svg
    ├── molienda.svg
    ├── prensa-francesa.svg
    ├── filtro-v60.svg
    ├── moka.svg
    └── cold-brew.svg

Convenciones de nombres

  • Todo en minúsculas, sin espacios, tildes ni ñ: prensa-francesa.svg, no Prensa Francesa.SVG.
  • La página principal se llama index.html: es la que abre el servidor por defecto.
  • Rutas relativas: css/styles.css. Nunca C:\Users\…, porque en otro equipo no existe.
  • Clases con BEM simplificado: bloque__elemento--modificador → tema__datos, boton--primario.

Herramientas

  • VS Code con la extensión Live Server: clic derecho en index.html → Open with Live Server. Recarga sola al guardar.
  • DevTools del navegador: F12; modo dispositivo con Ctrl + Shift + M.
  • Validador W3C: validator.w3.org para revisar el HTML.
Paso 2 · HTML

Todo empieza en el <head>: lo que el navegador lee antes de pintar

El <head> no se ve en pantalla, pero decide cómo se interpreta la página: idioma, codificación, tamaño en el celular, título y archivos que carga.

index.html 
<!DOCTYPE html>
<html lang="es" class="no-js">
<head>
  <!-- 1. Metadatos: codificación, vista móvil, título y descripción -->
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Tutorial: prepara café de especialidad en casa | AromaSur Café</title>
  <meta name="description" content="Tutorial paso a paso de AromaSur Café: cómo moler el grano y preparar café con prensa francesa, filtro V60, cafetera moka y cold brew.">
  <meta name="robots" content="noindex">
  <link rel="icon" href="img/logo.svg" type="image/svg+xml">

  <!-- 2. Antes de pintar: marca que JS está activo y aplica el tema guardado (evita parpadeos) -->
  <script>
    document.documentElement.classList.replace('no-js', 'js');
    let tema = null;
    try { tema = localStorage.getItem('tema'); } catch (e) { /* almacenamiento bloqueado */ }
    // Sin preferencia guardada, se respeta la del sistema operativo
    if (!tema) tema = matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
    document.documentElement.dataset.theme = tema;
  </script>

  <!-- 3. Estilos y comportamiento en archivos externos (separación de responsabilidades) -->
  <link rel="stylesheet" href="css/styles.css">
  <script src="js/main.js" defer></script>
</head>

Línea por línea

  • <!DOCTYPE html>: activa el modo estándar de HTML5.
  • lang="es": el lector de pantalla pronuncia en español y el traductor sabe el idioma.
  • charset="UTF-8": tildes, ñ y símbolos se muestran bien.
  • viewport: sin esta línea el celular simula una pantalla de 980 px y todo se ve diminuto.
  • <title> y description: texto de la pestaña y del resultado en Google.
  • <link rel="stylesheet">: el CSS va en el head para que la página aparezca ya con estilos.
  • defer: el JS se descarga en paralelo y se ejecuta cuando el HTML ya existe.

Detalle profesional: El pequeño script en línea marca la clase js y aplica el tema guardado antes de pintar, para evitar un parpadeo de colores al cargar.

Paso 5 · Requisito de la guía

La lista ordenada enlaza con cada tema usando anclas

Un enlace con href="#id" no cambia de página: desplaza la vista hasta el elemento que tiene ese id.

index.html · origen (el temario) 
<ol class="temario">
  <li><a href="#tema-molienda">Elegir y moler el grano</a></li>
  <li><a href="#tema-prensa">Prensa francesa</a></li>
  <li><a href="#tema-v60">Filtro V60</a></li>
  <li><a href="#tema-moka">Cafetera moka</a></li>
  <li><a href="#tema-cold-brew">Cold brew</a></li>
</ol>
index.html · destino (el tema) 
<article class="tema" id="tema-molienda">
  <h3>1. Elegir y moler el grano</h3>
  …
  <a class="tema__volver" href="#temario">Volver al temario</a>
</article>
href="#tema-molienda" id="tema-molienda"
  • <ol> porque los temas tienen orden (paso 1, 2, 3…). Si el orden no importara, sería <ul>.
  • El id debe ser único en la página y coincidir exactamente con el href (sin el #).
  • Cada tema tiene un enlace de regreso: el usuario nunca queda "perdido" al final de un tema largo.
css/styles.css 
html {
  scroll-behavior: smooth;
  scroll-padding-top: calc(var(--alto-encabezado) + 1rem); /* el encabezado fijo no tapa el tema */
}

¿Por qué? Como el encabezado es fijo (position: sticky), sin scroll-padding-top el título del tema quedaría escondido debajo de él al saltar.

Paso 6 · Requisito de la guía

Anatomía de un <article> de tema

Cada tema reúne lo que pide la guía (título, imagen y descripción) y suma datos rápidos y un paso a paso desplegable.

index.html 
<article class="tema" id="tema-molienda">
  <h3>1. Elegir y moler el grano</h3>
  <figure>
    <img src="img/molienda.svg" alt="Molino manual junto a granos enteros y café molido en tres tamaños: grueso, medio y fino"
         width="640" height="400" loading="lazy">
    <figcaption>El tamaño de la molienda cambia según el método.</figcaption>
  </figure>
  <ul class="tema__datos" aria-label="Datos del tema">
    <li>5 min</li>
    <li>Nivel básico</li>
  </ul>
  <p>
    Compra el café en grano y muélelo justo antes de prepararlo: así conserva sus aromas.
    Usa molienda gruesa para prensa y cold brew, media para filtro y fina para moka.
  </p>
  <details>
    <summary>Paso a paso</summary>
    <ol>
      <li>Revisa la fecha de tueste: lo ideal es usarlo dentro del primer mes.</li>
      <li>Pesa el café: unos 15 g por taza de 250 ml.</li>
      <li>Ajusta el molino al método y muele solo lo que vas a usar.</li>
    </ol>
  </details>
  <a class="tema__volver" href="#temario">Volver al temario</a>
</article>

La imagen correcta

  • alt describe lo que muestra la imagen para quien no la ve. No escribas "imagen de…".
  • Si la imagen es decorativa (el logo junto al nombre de la marca), usa alt="" para que el lector la ignore.
  • width y height reservan el espacio: el texto no "salta" cuando la imagen termina de cargar.
  • loading="lazy" descarga la imagen solo cuando el usuario se acerca a ella.
  • <figure> + <figcaption> asocian la imagen con su pie de foto.

Acordeón sin JavaScript

<details> y <summary> crean un bloque desplegable nativo: funciona con teclado (Enter), lo anuncian los lectores de pantalla y no necesita una sola línea de JS.

Tablas para datos y formularios accesibles

La guía pide incluir los elementos vistos en el componente. La demo agrega una tabla comparativa y un formulario de suscripción.

index.html · tabla 
<div class="tabla-contenedor" tabindex="0" role="region"
     aria-labelledby="titulo-comparativa">
  <table>
    <caption>Valores de referencia para una preparación</caption>
    <thead>
      <tr>
        <th scope="col">Método</th>
        <th scope="col">Molienda</th>
        …
      </tr>
    </thead>
    <tbody>
      <tr><th scope="row">Prensa francesa</th><td>Gruesa</td>…</tr>
    </tbody>
  </table>
</div>
  • <caption> es el título de la tabla.
  • scope="col" / scope="row" indican si el encabezado describe una columna o una fila.
  • El contenedor con overflow-x: auto permite deslizar la tabla en el celular; tabindex="0" deja hacerlo con el teclado.
  • Las tablas son para datos tabulares, nunca para maquetar la página.
index.html · formulario 
<div class="campo">
  <label for="correo">Correo electrónico</label>
  <input id="correo" name="correo" type="email" autocomplete="email" required
         aria-describedby="correo-error">
  <p class="campo__error" id="correo-error"></p>
</div>
  • <label for="correo"> se conecta con id="correo": al hacer clic en el texto se activa el campo y el lector lo anuncia.
  • type="email" muestra el teclado con @ en el celular y valida el formato.
  • autocomplete="email" permite autocompletar; required lo hace obligatorio.
  • aria-describedby conecta el campo con su mensaje de error.
  • Nunca uses solo el placeholder como etiqueta: desaparece al escribir.
Paso 8 · CSS

Cómo decide el navegador qué estilo aplicar

Una hoja de estilos es una lista de reglas. Cuando dos reglas afectan al mismo elemento, gana la más específica; si empatan, gana la que está más abajo.

Anatomía de una regla

.boton--primario {
  background-color: var(--color-primario);
}
selector: a quién propiedad: qué cambia valor: cómo queda

Especificidad (de menor a mayor)

  1. a etiqueta0,0,1
  2. .tema clase, :hover, [atributo]0,1,0
  3. #temario id1,0,0

En la demo, .js .navegacion__lista (0,2,0) le gana a .navegacion__lista (0,1,0) y oculta el menú solo cuando JS está activo.

Buena práctica: estiliza con clases; deja los id para anclas y JS, y evita !important.

Orden del archivo styles.css

  1. Variables: colores, radios, sombras
  2. Reset mínimo
  3. Base: tipografía, enlaces, imágenes
  4. Utilidades y accesibilidad
  5. Componentes: encabezado, héroe, temas…
  6. Media queries: tablet y escritorio
  7. Preferencias del usuario

De lo general a lo particular: así la cascada trabaja a tu favor.

Paso 11 · Grid

Grid organiza en DOS dimensiones a la vez

Filas y columnas. Es la herramienta para el layout de la página y para rejillas de tarjetas.

grid-template-columns: 1fr 2fr 1fr
1fr
2fr
1fr
1fr
2fr
1fr
  • fr = una fracción del espacio libre: aquí la columna central mide el doble.
  • gap separa filas y columnas.
  • Los hijos se ubican solos en las celdas, en orden.

repeat()

Evita repetir: repeat(3, 1fr) = 1fr 1fr 1fr.

minmax()

Tamaño con mínimo y máximo: minmax(17rem, 1fr) = nunca menos de 17rem, puede crecer.

auto-fit

repeat(auto-fit, minmax(17rem, 1fr)): el navegador calcula cuántas columnas caben. Responsive sin media queries.

grid-template-areas

Le pones nombre a las zonas y "dibujas" el layout: "temas lateral". Cada hijo se ubica con grid-area.

place-items

place-items: center centra en ambos ejes. Lo usamos para el número de cada tema del temario.

min()

min(100%, 17rem) evita que una tarjeta de 17rem desborde una pantalla de 320 px.

Practica en vivo

Comprueba cómo auto-fit cambia el número de columnas

Elige repeat(auto-fit, minmax(9rem, 1fr)) y reduce el ancho del contenedor: las columnas se reorganizan solas, igual que las tarjetas de la demo.

Cuatro usos de Grid en la página

Usamos Grid cuando necesitamos columnas definidas o una rejilla donde los elementos se alinean en filas y columnas al mismo tiempo.

1. Héroe: texto + imagen (1 → 2 columnas)

styles.css 
.heroe__grid {
  display: grid;
  gap: 2rem;
  align-items: center;
}

@media (min-width: 48rem) {
  .heroe__grid { grid-template-columns: 1.1fr 1fr; }
}

2. Diseño de página con áreas con nombre

styles.css 
.diseno {
  grid-template-columns: minmax(0, 1fr) 18rem;
  grid-template-areas: "temas lateral";
}
.temas   { grid-area: temas; }
.lateral { grid-area: lateral; }

3. Rejilla de temas: auto-fit (sin media queries)

styles.css 
.temas__grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 17rem), 1fr));
  gap: 1.5rem;
  margin-top: 1rem;
}

4. Pie de página: columnas que se apilan solas

styles.css 
.pie__grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(14rem, 1fr));
  gap: 1.5rem;
}

Paso 12 · Responsive

Primero el celular, luego se agrega para pantallas grandes

La mayoría de usuarios entra desde el celular. Escribimos los estilos base para la pantalla pequeña y usamos @media (min-width: …) para sumar cambios cuando hay más espacio.

css/styles.css 
/* BASE = celular: una columna, menú oculto tras el botón */
.heroe__grid {
  display: grid;
  gap: 2rem;
}

/* Tablet: 48rem = 768px → se SUMAN cambios */
@media (min-width: 48rem) {
  .heroe__grid { grid-template-columns: 1.1fr 1fr; }
  .menu-toggle { display: none; }
}

/* Escritorio: 64rem = 1024px */
@media (min-width: 64rem) {
  .diseno {
    grid-template-columns: minmax(0, 1fr) 18rem;
  }
}

Móvil < 768 px

Una columna, menú hamburguesa, tabla con desplazamiento horizontal.

Tablet ≥ 768 px

Héroe en 2 columnas, menú en fila, tarjetas en 2 columnas (auto-fit).

Escritorio ≥ 1024 px

Aparece el lateral fijo al lado de los temas (grid-template-areas).

Unidades que se adaptan

  • rem para tamaños y espacios: respeta el tamaño de letra que eligió el usuario.
  • %, fr y min(100% - 2rem, 72rem) para anchos fluidos.
  • clamp(2rem, 5vw + 1rem, 3.5rem): el h1 crece con la pantalla, con mínimo y máximo.
  • 60ch: líneas de lectura de ~60 caracteres.

Paso 13 · JavaScript

El patrón de todo script: seleccionar, escuchar, reaccionar

El DOM es la representación del HTML como objetos que JavaScript puede leer y cambiar. Cada interacción sigue los mismos cuatro pasos.

1 Seleccionar

2 Escuchar

3 Reaccionar

función que decide

4 Modificar el DOM

atributos, clases, texto

js/main.js · menú móvil 
const encabezado = document.querySelector('.encabezado');
const botonMenu = document.querySelector('.menu-toggle');
const textoMenu = botonMenu.querySelector('.solo-lectores');

function cambiarMenu(abrir) {
  encabezado.dataset.menu = abrir ? 'abierto' : 'cerrado'; // el CSS reacciona a este atributo
  botonMenu.setAttribute('aria-expanded', String(abrir));   // informa el estado al lector de pantalla
  textoMenu.textContent = abrir ? 'Cerrar menú' : 'Abrir menú';
}

botonMenu.addEventListener('click', () => {
  const estaAbierto = botonMenu.getAttribute('aria-expanded') === 'true';
  cambiarMenu(!estaAbierto);
});

Qué hace

  • Al hacer clic, alterna data-menu="abierto" en el encabezado.
  • El CSS decide cómo se ve el menú abierto; JS solo cambia el estado.
  • aria-expanded le dice al lector de pantalla si el menú está abierto o cerrado.
  • Los enlaces cierran el menú y Esc también, devolviendo el foco al botón.

¿Por qué un atributo y no estilos en JS? Cambiar element.style.display mezcla las capas. Con un atributo de estado, la apariencia sigue viviendo en el CSS y el código queda más limpio.

Paso 14 · Interactividad

Modo oscuro: JS cambia un atributo, CSS cambia los colores

Gracias a las variables, el modo oscuro no reescribe componentes: solo redefine los tokens dentro de [data-theme="dark"].

js/main.js · modo oscuro 
function aplicarTema(tema) {
  raiz.dataset.theme = tema;                         // activa las variables de [data-theme="dark"]
  const oscuro = tema === 'dark';
  botonTema.setAttribute('aria-pressed', String(oscuro));
  textoTema.textContent = oscuro ? 'Desactivar modo oscuro' : 'Activar modo oscuro';
}

aplicarTema(raiz.dataset.theme || 'light'); // sincroniza el botón con el tema aplicado en <head>

botonTema.addEventListener('click', () => {
  const nuevoTema = raiz.dataset.theme === 'dark' ? 'light' : 'dark';
  aplicarTema(nuevoTema);
  try {
    localStorage.setItem('tema', nuevoTema); // se recuerda en la próxima visita
  } catch (error) {
    // Navegación privada o almacenamiento bloqueado: el tema solo dura esta visita
  }
});
css/styles.css 
[data-theme="dark"] {
  --color-primario: #E3B98F;
  --color-texto: #F3ECE4;
  --color-fondo: #17120F;
  --color-superficie: #221B17;
  /* … el resto de componentes no cambia */
}
  • localStorage recuerda la elección para la próxima visita. Va en try/catch porque el navegador puede bloquearlo (modo privado).
  • Si el usuario nunca eligió, se respeta la preferencia del sistema operativo con prefers-color-scheme.
  • aria-pressed indica que el botón es un interruptor (encendido/apagado).
  • Los colores oscuros también deben cumplir contraste de 4.5:1 con el texto.
Paso 15 · Formularios

Validar, avisar y guiar al usuario

La API validity del navegador ya sabe si el correo está vacío o mal escrito; nosotros mostramos un mensaje claro y lo anunciamos a los lectores de pantalla.

js/main.js · formulario 
formulario.noValidate = true; // usamos mensajes propios en lugar de las burbujas del navegador

function validarCorreo() {
  let mensaje = '';
  if (correo.validity.valueMissing) {
    mensaje = 'Escribe tu correo electrónico.';
  } else if (correo.validity.typeMismatch) {
    mensaje = 'El correo debe tener el formato nombre@dominio.com.';
  }
  errorCorreo.textContent = mensaje;
  correo.setAttribute('aria-invalid', String(mensaje !== ''));
  return mensaje === '';
}

correo.addEventListener('blur', validarCorreo); // valida al salir del campo

formulario.addEventListener('submit', (evento) => {
  evento.preventDefault(); // evita recargar la página: no hay servidor en esta demo
  estado.textContent = '';

  if (!validarCorreo()) {
    correo.focus(); // lleva al usuario directo al campo con error
    return;
  }

  const metodo = formulario.metodo.selectedOptions[0].textContent;
  estado.textContent = `¡Listo! Te enviaremos recetas de ${metodo}.`;
  formulario.reset();
});

Buenas prácticas aplicadas

  • preventDefault() evita recargar la página (esta demo no tiene servidor).
  • aria-invalid="true" marca el campo con error para tecnologías de apoyo.
  • El mensaje de error está conectado con aria-describedby.
  • El mensaje de éxito está en una región aria-live="polite": se anuncia sin mover el foco.
  • Ante un error, el foco vuelve al campo: el usuario sabe dónde corregir.

Seguridad: la validación en el navegador mejora la experiencia, pero se puede saltar. En un proyecto real, el servidor siempre vuelve a validar los datos.

Paso 16 · Calidad

Accesibilidad (WCAG 2.1) y cómo probarla

Una página accesible funciona para todos: personas con discapacidad visual, motriz o cognitiva, y también para quien navega con sol en la pantalla o con una sola mano.

Perceptible

Texto alternativo en imágenes, contraste AA (4.5:1) verificado en modo claro y oscuro, texto que escala con rem.

Operable

Todo funciona con teclado, foco visible con :focus-visible, enlace de salto, áreas táctiles de 48 px.

Comprensible

lang="es", etiquetas visibles en el formulario, errores que explican cómo corregir.

Robusto

HTML semántico y válido, aria-expanded / aria-pressed / aria-live solo donde hace falta.
