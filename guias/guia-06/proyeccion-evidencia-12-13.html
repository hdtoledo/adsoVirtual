EV02 · Concepto

Una interfaz se arma como un juego de bloques

Un componente es una pieza de interfaz reutilizable con una función, una estructura HTML, unos estilos y unos estados definidos. La metodología Atomic Design los ordena de lo más simple a lo más complejo.

1
Átomos

La pieza mínima; no se puede dividir sin perder sentido.

Botón · insignia · casilla · contador

2
Moléculas

Átomos que trabajan juntos para una tarea.

Campo de texto (etiqueta + control + error) · tarjeta de producto · chips

3
Organismos

Secciones completas formadas por moléculas.

Barra de navegación · formulario de Login · rejilla del catálogo · diálogo del pedido

4
Plantillas

La distribución de los organismos en la pantalla, sin contenido real.

Plantilla de autenticación (2 columnas) · plantilla de aplicación

5
Páginas

La plantilla con contenido real: lo que ve el usuario.

Login · Registro · Catálogo

¿Por qué pensar en componentes?

  • Se diseña y se programa una vez y se usa en muchas pantallas.
  • Un cambio (por ejemplo el color del botón) se hace en un solo lugar.
  • La interfaz es consistente: el usuario aprende una vez cómo funciona.
  • Prepara el camino a React o Angular, donde todo es un componente.

En Figma ya lo hiciste: los components con variantes de la EV09–10 son exactamente esto.

Los archivos se organizan igual que los componentes

index.html · orden de carga 
<!-- Estilos por capas: tokens → base → componentes → layouts -->
<link rel="stylesheet" href="css/tokens.css">
<link rel="stylesheet" href="css/base.css">
<link rel="stylesheet" href="css/componentes.css">
<link rel="stylesheet" href="css/layouts.css">

<!-- Scripts: primero los compartidos, luego el de la página -->
<script src="js/ui.js" defer></script>
<script src="js/validacion.js" defer></script>
<script src="js/login.js" defer></script>

Decisiones de arquitectura

  • Capas de CSS: cada archivo puede usar lo del anterior, nunca al revés.
  • JS compartido primero (ui.js, validacion.js) y luego el de la pantalla. defer respeta ese orden.
  • Objetos globales (AromaUI, Validacion) en lugar de import: los módulos ES no funcionan al abrir el HTML con doble clic (file://).

tokens.css: una sola fuente de verdad para el diseño

Cada estilo de Figma tiene su variable. Los comentarios guardan el contraste verificado: quien cambie un color sabe qué debe seguir cumpliendo.

  --color-primario-700: #5B3A29;  /* botones, títulos       · 10.09:1 sobre blanco */
  --color-primario-800: #45291C;  /* hover del botón         */

  --espacio-2: 0.5rem;   /*  8 px */
  --espacio-3: 0.75rem;  /* 12 px */

  --espacio-6: 1.5rem;   /* 24 px */
  /* … */

Cómo se usan

Los componentes nunca escriben un color:

background-color: var(--color-primario-700);

clamp() en la tipografía

clamp(1.5rem, 1.1rem + 1.5vw, 2rem) hace que el h1 pase de 24 px en el celular a 32 px en escritorio, igual que los dos tamaños definidos en Figma.

EV03 · Paso 4

Las reglas viven en el HTML; la validación es una sola función

El campo declara qué exige (required, type, pattern, minlength) y sus mensajes en data-msg-*. Un solo archivo JS valida todos los formularios del proyecto.

index.html · campo de correo 
<div class="campo">
  <label class="campo__etiqueta" for="correo">Correo electrónico</label>
  <input class="campo__control" id="correo" name="correo" type="email"
         autocomplete="email" placeholder="nombre@negocio.com" required
         aria-describedby="correo-error"
         data-msg-requerido="Escribe tu correo electrónico."
         data-msg-formato="Escribe un correo válido, por ejemplo nombre@negocio.com.">
  <p class="campo__error" id="correo-error"></p>
</div>
js/validacion.js 
function validarCampo(campo) {
  let mensaje = '';
  for (const [estado, atributo, porDefecto] of MENSAJES) {
    if (campo.validity[estado]) {
      mensaje = campo.dataset[atributo] || porDefecto;
      break;
    }
  }

  const error = document.getElementById(`${campo.id}-error`);
  if (error) error.textContent = mensaje;
  campo.setAttribute('aria-invalid', String(mensaje !== ''));
  return mensaje === '';
}
  • validity es una API del navegador: ya sabe si el campo está vacío (valueMissing) o mal escrito (typeMismatch).
  • dataset.msgRequerido lee el atributo data-msg-requerido.
  • Login y Registro solo llaman Validacion.conectar(formulario, alEnviar).

  AromaUI.cargando(botonIngresar, true, 'Ingresando…');

    boton.addEventListener('click', () => {
      const visible = campo.type === 'text';
      campo.type = visible ? 'password' : 'text';
      boton.setAttribute('aria-pressed', String(!visible));
      boton.setAttribute('aria-label', visible ? 'Mostrar contraseña' : 'Ocultar contraseña');
    });
  });
}
  • aria-pressed indica si el interruptor está activo y el CSS cambia el icono (ojo / ojo tachado).
  • aria-label cambia entre "Mostrar" y "Ocultar contraseña".
  • Se activa solo en cualquier página que tenga data-mostrar-clave: es un comportamiento del componente, no de la pantalla.

js/catalogo.js · crear tarjeta 
function crearTarjeta(producto) {
  const tarjeta = plantilla.content.cloneNode(true); // copia del <template> definido en el HTML
  const img = tarjeta.querySelector('img');
  img.src = `img/bolsa-${producto.perfil}.svg`;
  img.alt = `Bolsa de café ${producto.nombre}`;
  tarjeta.querySelector('.tarjeta-producto__titulo').textContent = producto.nombre;
  tarjeta.querySelector('.tarjeta-producto__origen').textContent = producto.origen;
  tarjeta.querySelector('.tarjeta-producto__notas').textContent = producto.notas;

  const insignia = tarjeta.querySelector('.insignia');
  insignia.textContent = PERFILES[producto.perfil];
  insignia.classList.add(`insignia--${producto.perfil}`);

  tarjeta.querySelector('[data-precio]').textContent = pesos.format(producto.precio);
  const boton = tarjeta.querySelector('[data-agregar]');
  boton.dataset.agregar = producto.id;
  boton.setAttribute('aria-label', `Agregar ${producto.nombre} al pedido`);
  return tarjeta;
}

textContent, no innerHTML: si un nombre de producto trajera código malicioso, textContent lo muestra como texto. Con innerHTML se ejecutaría (ataque XSS).

EV03 · Paso 10

Agregar, revisar y confirmar el pedido

Tres componentes trabajan juntos: el botón de la tarjeta, el toast que confirma y el diálogo que resume el pedido con el total en pesos colombianos.

rejilla.addEventListener('click', (evento) => {
  const boton = evento.target.closest('[data-agregar]');
  if (!boton) return;
  const producto = PRODUCTOS.find((p) => p.id === boton.dataset.agregar);
  estado.pedido.set(producto.id, (estado.pedido.get(producto.id) || 0) + 1);

});

js/ui.js · toast 
function toast(mensaje, tipo = 'info') {
  const aviso = document.createElement('div');
  aviso.className = `toast toast--${tipo}`;
  aviso.textContent = mensaje;                  // textContent evita inyección de HTML (XSS)
  obtenerRegion().append(aviso);

  setTimeout(() => {
    aviso.dataset.saliendo = '';
    setTimeout(() => aviso.remove(), 200);
  }, 3500);
}

La región del toast tiene aria-live="polite": el lector de pantalla anuncia cada mensaje sin mover el foco.
