Concepto base

El código se escribe una vez, pero se lee diez veces

Un estándar de codificación es el conjunto de convenciones compartidas por un equipo para que cualquier archivo parezca escrito por una sola persona, sin importar quién lo programó.

Sin estándar de codificación

class prod {
 constructor(p,s){this.p=p;this.s=s;}
 calc(c){var t=0;if(c>0)t=this.p*c;return t;}
}
  • Nombres crípticos (p, s, c) y uso de var obsoleto.
  • Propiedades públicas sin validar: cualquiera asigna un precio negativo.
  • Revisiones en Git llenas de conflictos por espacios y llaves distintas.

Con estándar (AromaSur · JavaScript)

export class Producto {
  #precioCop;

  calcularSubtotal(cantidad) {
    if (!Number.isInteger(cantidad) || cantidad <= 0) {
      throw new RangeError('Cantidad inválida');
    }
    return this.#precioCop * cantidad;
  }
}

Regla 2 · Variables y constantes

El nombre de una variable dice qué guarda; const protege su valor

Esta es una de las secciones obligatorias de la guía. En JavaScript moderno siempre se usa const por defecto, let solo cuando se reasigna y nunca var.

Elemento Regla en JavaScript Correcto Incorrecto
Variable / propiedadSustantivo descriptivo en camelCase con const / let.const precioCop = 38500;var p = 38500; / Precio_Cop
BooleanoPregunta afirmativa: es, tiene, esta o is/has.tieneStock, esStockBajo, esActivoestado, flag, noInactivo
Constante fijaUPPER_SNAKE_CASE (+ Object.freeze en catálogos).STOCK_MINIMO = 5, ESTADOS_PEDIDOstockMinimo = 5 / usar 5 suelto
Arreglo / listaNombre en plural; sin sufijos redundantes (Array, Lista).productos, items, pedidosPendienteslistaProductosArray, item
Dinero y fechasEnteros en pesos COP o centavos (Number.isInteger); fechas en ISO 8601.precioCop: 38500, creadoEn: '2026-11-23'precio: '38.500' / 0.1 + 0.2

¿Por qué evitar decimales flotantes en dinero? En JavaScript 0.1 + 0.2 === 0.30000000000000004; guardar precios en pesos COP enteros (o en centavos enteros) garantiza totales exactos.

Regla 3 · Clases (POO)

Clases encapsuladas con campos privados # y orden interno fijo

Aplica el paradigma orientado a objetos en JavaScript moderno: campos privados reales (#), validaciones en el constructor y seis bloques en orden fijo.

src/modelo/producto.js (extracto de la demo) 
export class Producto {
  static STOCK_MINIMO = 5;                       // 1. Constantes

  #codigo;                                       // 2. Campos privados (#)
  #nombre;
  #precioCop;
  #cantidadDisponible;

  constructor({ codigo, nombre, precioCop,       // 3. Constructor + validación
    cantidadDisponible }) {
    // … guard clauses de codigo, nombre y stock (ver demo)
    if (!Number.isInteger(precioCop) || precioCop <= 0) {
      throw new RangeError('Precio inválido');
    }
    this.#codigo = codigo.trim();
    this.#nombre = nombre.trim();
    this.#precioCop = precioCop;
    this.#cantidadDisponible = cantidadDisponible;
  }

  esStockBajo() {                                // 4. Métodos de negocio
    return this.#cantidadDisponible <= Producto.STOCK_MINIMO;
  }
  get codigo() { return this.#codigo; }          // 5. Getters de solo lectura
  #validarCantidad(cantidad) {                   // 6. Privados al final
    if (!Number.isInteger(cantidad) || cantidad <= 0) {
      throw new RangeError('La cantidad debe ser un entero mayor que cero');
    }
  }
}

Orden interno oficial

  1. 1. Constantes static en UPPER_SNAKE_CASE
  2. 2. Campos privados # (encapsulamiento real)
  3. 3. constructor con objeto desestructurado y validación
  4. 4. Métodos públicos de negocio en camelCase
  5. 5. get de solo lectura (sin set innecesarios)
  6. 6. Métodos privados # auxiliares al final

Catálogos cerrados: usa export const ESTADOS_PEDIDO = Object.freeze({ PENDIENTE: 'PENDIENTE', ... }) en lugar de textos repetidos por el código.

Regla 4 · Funciones y métodos

Funciones cortas, con verbo claro y validaciones tempranas

Ya sea un método de clase, una función auxiliar o un controlador Express, una función hace una sola tarea y falla rápido ante datos inválidos.

Cinco reglas para funciones limpias

  • Verbo + sustantivo en camelCase: agregarProducto, calcularTotalCop, buscarProductoPorCodigo.
  • Tamaño acotado: idealmente 10 a 25 líneas; si supera 40, divide en funciones auxiliares.
  • Máximo 3 parámetros: si necesita más, recibe un objeto desestructurado ({ codigo, nombre, precioCop }).
  • Guard clauses y async/await: valida arriba para evitar if anidados y usa async/await en lugar de callbacks anidados.
  • Retornos inmutables: devuelve copias (Object.freeze([...this.#items])) para proteger el estado interno.
src/modelo/pedido.js (guard clauses) 
agregarProducto(producto, cantidad) {
  // Validaciones tempranas: sin pirámide de if anidados
  if (!(producto instanceof Producto)) {
    throw new TypeError('Se requiere una instancia válida de Producto');
  }
  if (this.#estado !== ESTADOS_PEDIDO.PENDIENTE) {
    throw new Error('Solo se pueden agregar ítems a un pedido pendiente');
  }

  producto.descontarStock(cantidad);
  this.#items.push(Object.freeze({
    codigoProducto: producto.codigo,
    nombreProducto: producto.nombre,
    precioCop: producto.precioCop,
    cantidad,
    subtotalCop: producto.precioCop * cantidad,
  }));
}
Regla 5 · Formato

Un formato uniforme evita bugs sutiles y ruido en Git

Define estas seis reglas en el informe; luego .editorconfig y Prettier las aplicarán automáticamente al guardar.

Sangría de 2 espacios

2 espacios en todo el repositorio (JS, JSX, JSON, CSS y SQL). Nunca mezclar tabs y espacios.

Ancho máximo 100 caracteres

Facilita comparar dos archivos lado a lado al revisar pull requests en GitHub.

Igualdad estricta y llaves

Siempre === / !== (nunca ==) y siempre llaves K&R en if/for, incluso de una línea (regla del equipo: endurecemos Airbnb con curly: 'all').

Comillas, punto y coma e imports

Comillas simples '...', punto y coma al final, y orden de import: nativos → npm → locales.

Codificación UTF-8 y LF

Todos los archivos en UTF-8 y salto de línea LF para evitar diffs falsos entre Windows y Linux.

Coma final (trailing comma)

Coma al final de objetos y arreglos multilínea: agregar una propiedad solo toca una línea en Git.

Por qué prohibir ==: en JavaScript '0' == false y '' == 0 evalúan a true por coerción implícita. Con === se comparan tipo y valor.

Regla 6 · Documentación y errores

Comenta el "por qué" con JSDoc y maneja errores en Express

Las actividades AA3, AA4 y AA5 piden "código comentado". Usa JSDoc en funciones y servicios públicos; evita comentarios que solo repiten la línea siguiente.

JSDoc vs comentario redundante 
// MAL: repite lo que ya dice el código
// Resta la cantidad al stock disponible
this.#cantidadDisponible -= cantidad;

// BIEN: documenta el contrato público con JSDoc
/**
 * Descuenta unidades del inventario tras validar disponibilidad.
 * @param {number} cantidad - Unidades solicitadas (entero > 0)
 * @throws {RangeError} Si la cantidad no es un entero positivo
 * @throws {Error} Si no hay stock suficiente
 */
descontarStock(cantidad) { … }

Reglas de manejo de errores

  • Errores descriptivos: usa TypeError (tipo inválido), RangeError (rango) y Error de dominio.
  • Prohibido catch (err) {} vacío: oculta fallos reales en promesas y consultas SQL.
  • Middleware central en Express: delega fallos con next(error) y responde JSON uniforme sin exponer error.stack.
  • Sin código comentado muerto ni console.log olvidados: para historial ya existe Git.
Coherencia entre capas

BD relacional, Express y React hablando el mismo idioma

Tu informe debe cubrir las tres capas reales de AromaSur para que el código de la AA2 a la AA5 mantenga coherencia de extremo a extremo.

Front-end · React (AA4)

  • Componentes funcionales: PascalCase (TarjetaCafe.jsx); un componente principal por archivo.
  • Hooks: prefijo use (usePedidos.js).
  • Eventos: handle en interno (handleEnviar) y on en props (onConfirmar).
  • Estilos: clases CSS en kebab-case o utilidades Tailwind consistentes.

Back-end · Node.js + Express

  • Capas separadas: rutas → controladores → servicios → repositorios.
  • Endpoints REST: plural y kebab-case (/api/v1/pedidos), verbos solo en HTTP (GET/POST/PATCH).
  • JSON: claves en camelCase (precioCop).
  • Configuración: solo en process.env (UPPER_SNAKE_CASE).

Base de datos · SQL Relacional

  • Tablas: snake_case en plural (productos, detalle_pedidos).
  • Columnas: snake_case singular (precio_cop, creado_en).
  • Llaves: id como PK y pedido_id como FK explícita.
  • Sentencias SQL: palabras clave en MAYÚSCULAS (SELECT, WHERE, INNER JOIN).

export class Producto {
  static STOCK_MINIMO = 5;
  #codigo;
  #nombre;
  #precioCop;
  #cantidadDisponible;

  constructor({ codigo, nombre, precioCop, cantidadDisponible }) {
    if (typeof codigo !== 'string' || !codigo.trim()) {
      throw new TypeError('El código del producto es obligatorio');
    }
    if (typeof nombre !== 'string' || !nombre.trim()) {
      throw new TypeError('El nombre del producto es obligatorio');
    }
    if (!Number.isInteger(precioCop) || precioCop <= 0) {
      throw new RangeError('El precio en COP debe ser un entero mayor que cero');
    }
    if (!Number.isInteger(cantidadDisponible) || cantidadDisponible < 0) {
      throw new RangeError('El stock inicial debe ser un entero mayor o igual a cero');
    }

    this.#codigo = codigo.trim();
    this.#nombre = nombre.trim();
    this.#precioCop = precioCop;
    this.#cantidadDisponible = cantidadDisponible;
  }

  tieneStock(cantidadSolicitada) {
    return Number.isInteger(cantidadSolicitada)
      && cantidadSolicitada > 0
      && this.#cantidadDisponible >= cantidadSolicitada;
  }

  esStockBajo() {
    return this.#cantidadDisponible <= Producto.STOCK_MINIMO;
  }

  descontarStock(cantidad) {
    this.#validarCantidad(cantidad);
    if (!this.tieneStock(cantidad)) {
      throw new Error(`Stock insuficiente para el producto ${this.#codigo}`);
    }
    this.#cantidadDisponible -= cantidad;
  }

  get codigo() { return this.#codigo; }
  get nombre() { return this.#nombre; }
  get precioCop() { return this.#precioCop; }
  get cantidadDisponible() { return this.#cantidadDisponible; }

  #validarCantidad(cantidad) {
    if (!Number.isInteger(cantidad) || cantidad <= 0) {
      throw new RangeError('La cantidad debe ser un entero mayor que cero');
    }
  }
}

Reglas no negociables

Un estándar profesional también prohíbe código inseguro

Incluir una sección de codificación segura en tu informe prepara directamente el back-end en Express + SQL (AA2–AA3) y el servicio de autenticación (AA5).

1. Cero secretos en código o en el cliente React

Credenciales de BD y llaves JWT van en .env (ignorado en Git) y se leen con process.env solo en Node.js; nunca en variables VITE_.

2. Consultas SQL parametrizadas (cero concatenación)

Usar siempre parámetros (pool.execute('SELECT ... WHERE codigo = ?', [codigo]) en MySQL o $1 en PostgreSQL); nunca plantillas `... ${codigo}`.

3. Contraseñas siempre con hash (AA5)

Guardar contraseñas con bcrypt o argon2, nunca en texto plano ni impresas en logs de consola.

4. Validar en Express y prevenir XSS en React

Validar el req.body en el servidor (ej. con Zod), no devolver error.stack al cliente y evitar dangerouslySetInnerHTML con datos sin sanear.
