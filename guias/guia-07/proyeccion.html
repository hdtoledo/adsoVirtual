AA1 · 40 horas

Configurar herramientas de versionamiento para control de código, de acuerdo con las metodologías de desarrollo

Antes de escribir código se planea cómo se construirá y se prepara el control de versiones: todo lo que se programe en la guía vivirá en un repositorio Git.

AA1-EV01Conocimiento Sesión lista

Informe técnico de plan de trabajo para construcción de software

Informe técnico que, a partir de las características del software, especifica las herramientas y tecnologías de versionamiento que se usarán para construirlo. Se explica con el caso AromaSur Café: selección justificada de Git, plataforma remota, estrategia de ramas, convenciones y plan de trabajo.

Tecnologías

Las herramientas que usarás durante la guía

La guía menciona Spring Boot, React, Android, Swift y Node como frameworks para el desarrollo ágil. Cada actividad indica cuál aplicar; elige según tu proyecto y justifícalo en el plan de trabajo (AA1-EV01).

Versionamiento

Git + GitHub o GitLab

AA1 a AA5: todo proyecto se versiona y se entrega con el enlace del repositorio.

Datos

MySQL / PostgreSQL + JDBC

AA2-EV01: conexión a la base de datos y operaciones CRUD.

Web con Java

Servlets + JSP

AA2-EV02: formularios HTML procesados con GET y POST.

Frameworks

Spring Boot (web) · Android (móvil)

AA3: módulos con frameworks para el desarrollo ágil.

Front-end

React (componentes y JSX)

AA4: taller, definición de componentes y código.

Servicios web

API REST (Java, Node.js o PHP)

AA5: registro e inicio de sesión y las API del proyecto.

Pruebas de API

Postman

AA5-EV02 y EV04: testing, video y archivo de endpoints.

Editor

VS Code / IntelliJ IDEA / Android Studio

Según la tecnología de cada actividad.

Nombre de las carpetas comprimidas

La guía pide el nombre del aprendiz y el número de la evidencia:

NOMBRE_APELLIDO_AA3_EV01.zip

En la AA2 aparece sin guion bajo (NOMBREAPELLIDO_AA2_EV01) y en la AA5-EV03 y EV04 el texto repite EV01 y EV02. Usa siempre el número real de la evidencia que entregas.

Revisión final: Antes de comprimir, descomprime una copia en otra carpeta y verifica que el proyecto abre y que el enlace del repositorio es público o que el instructor tiene acceso.

Evaluación

Cómo se evalúa la guía

Cada evidencia tiene su lista de chequeo (IE-GA7-220501096-AAx-EVxx). Estos son los criterios oficiales agrupados por actividad.

AA1

Interpreta el informe de diseño para definir el plan de trabajo · Define estándares de codificación · Selecciona y configura herramientas de versionamiento.

AA2 a AA4

Codifica los módulos del software stand-alone, web y móvil, de acuerdo con las especificaciones del diseño y el estándar de codificación.

AA5

Crea servicios web para disponer de métodos reutilizables en el software.

Recomendaciones

  • Organiza tu tiempo: la guía es exigente (498 horas).
  • Consulta los componentes formativos antes de cada evidencia.
  • Asiste a los encuentros de asesoría virtual con tus dudas concretas.
  • Versiona desde el primer día y sube cambios con frecuencia.
  • Revisa la lista de chequeo antes de subir a Zajuna.
